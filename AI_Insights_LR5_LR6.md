Примітка щодо процесу. Усі артефакти створено в діалозі з Claude (Anthropic): студентка формулювала вимоги й рішення (вибір Neo4j, три сховища, назва Novelize), Claude готував чернетки та проводив аудит за пунктами методичних промптів. Окремі сесії з промптами-аудиторами дослівно не запускалися; аудит виконано в тому самому діалозі за структурою цих промптів. Якщо потрібно мати дослівні звіти, промпти з методички слід запустити в окремій сесії та замінити ними розділи «Звіт аудитора».

## ЛР№5

### Завдання 1. SRS (ISO/IEC/IEEE 29148)
- **Перша версія.** Вимоги з Розділу 1 перенесено в SRS: функціональні вимоги з ідентифікаторами SRS-FUN-01…16 (відповідність 7 Core Features), нефункціональні за категоріями.
- **Аудит (критерії: однозначність, вимірюваність, перевірюваність, унікальні ID).** Виявлено: нефункціональні вимоги без чисел («швидко», «надійно»); відсутній метод перевірки; відсутній глосарій.
- **Дії.** Додано числові пороги (p95 < 200 мс при 500 RPS; аналіз ≤ 30 с; перевірка узгодженості ≤ 3 с; доступність ≥ 99,5 %; RPO ≤ 24 год; RTO ≤ 60 хв), таблицю методів верифікації (k6, SonarQube, Trivy, OWASP ZAP тощо) і глосарій.

### Завдання 2–3. C4 Context, Container, Component (Mermaid)
- **Перша версія.** Діаграми з узагальненими підписами стрілок («використовує»), без API Gateway, Identity Provider та Observability.
- **Аудит.** Стрілки без протоколу; відсутні периметр безпеки та спостережуваність; на компонентному рівні контролер напряму звертався до бази.
- **Дії.** Усі стрілки підписано протоколом (REST / HTTP, Kafka protocol, Cypher / Bolt, SQL / TCP, SMTP / TLS); додано API Gateway (NGINX), Keycloak, Observability Stack; на рівні Component впроваджено порти й адаптери (`EntityGraphPort`, `Neo4jGraphRepository`), `IdempotencyGuard`, `OutboxPublisher`, `JwtAuthGuard`.
- **Відхилено.** Реплікацію баз даних: цільове середовище — Docker Compose, Neo4j Community не підтримує кластеризацію. Зв'язки IdP → PostgreSQL та сервіс → Observability не показано на діаграмі для читабельності; вони описані текстом під діаграмою.

### Завдання 4. ADR-001 (шаблон Nygard)
- **Перша версія.** Обґрунтування Neo4j через «швидше» та «зручніше», лише позитивні наслідки.
- **Аудит.** Аргументи оцінні та не мають технічних критеріїв; відсутні альтернативи й негативні наслідки.
- **Дії.** Розглянуто альтернативи (PostgreSQL з рекурсивними CTE, Apache AGE, ArangoDB); наведено технічні критерії; додано негативні наслідки (третє сховище, відсутність online-бекапу та кластеризації в Community, Eventual Consistency, спільний доступ до Neo4j, GPLv3). Прямо зазначено, що для 1 000 вузлів обидва підходи (A та C) досягають p95 ≤ 3 с.

## ЛР№6

### Завдання 1. Схема даних
- **Перша версія.** ERD для PostgreSQL (11 таблиць), схема графа Neo4j (classDiagram), колекція ChromaDB.
- **Звіт аудитора (за пунктами промпта).**
  1. Нормалізація: 3NF дотримано; `entity_ids uuid[]` та `details jsonb` у `consistency_findings` — свідома денормалізація, бо посилання на вузли іншого сховища.
  2. Цілісність: зв'язок `text_statistics` з `analysis_runs` позначено 1 : 1, хоча рядок існує лише для COMPLETED; між схемами сервісів зовнішні ключі неможливі.
  3. Типи: `row_version` мав різні типи (`smallint` / `int`); потрібен план індексів (часткові, GIN, HNSW).
  4. Прогалини: відсутні `deleted_at`, оптимістичне блокування, `error_code`, ключ ідемпотентності для outbox; у графі відсутнє джерело значення атрибута.
- **Дії.** Зв'язок змінено на 1 : 0..1; `row_version` уніфіковано до `int`; додано `deleted_at`, `row_version`, `error_code` з CHECK, `outbox_events`, `processed_events`, `Attribute.source_node_id`; складено план індексування (часткові B-tree, UNIQUE-обмеження однієї активної перевірки на книгу, GIN для `entity_ids`, HNSW cosine у ChromaDB).
- **Відхилено.** Партиціювання `text_versions` (обсяг даних не виправдовує); зовнішні ключі між схемами сервісів.

### Завдання 2. OpenAPI
- **Перша версія.** Чотири ендпоінти (створення версії фрагмента, запуск перевірки узгодженості, статус, перелік знахідок), схеми запитів і відповідей, `bearerAuth`.
- **Звіт аудитора.**
  1. Синтаксис: файл валідний за OpenAPI 3.0.3 (перевірено `openapi-spec-validator`).
  2. Best practices: іменники в множині, асинхронна операція повертає 202 з `Location`, пагінація `limit` / `offset`.
  3. Помилки: описано 400, 401, 403, 404, 409, 413, 429 (з `Retry-After`), 500, 503 у форматі RFC 9457.
  4. Безпека: `bearerAuth` (JWT RS256), вимога на рівні кореня документа.
  - Зауваження: `error_code` у `ConsistencyRun` не обмежено переліком.
- **Дії.** Додано `enum` для `error_code`; обмеження `maxLength` / `minimum` / `pattern` для полів.
- **Відхилено.** Заголовок `Idempotency-Key` для створення версії: дублікати відсікаються за `content_sha256`.

### Завдання 3. Алгоритми
- **Перша версія.** Три алгоритми: перевірка узгодженості, смислові повтори, публікація outbox.
- **Звіт нормоконтролера.**
  1. Нормоконтроль: `:=` для присвоювання, `=` лише в умовах, AND / OR / NOT великими, індекси `X[i]`.
  2. Логіка: якщо в книзі немає персонажів, перевірка часової хронології пропускалася; повтори читання графа обмежувалися умовою `a ≤ 3`, що давало 4 виклики; цикл по персонажах мав ліміт часу, а цикл по `BEFORE` — ні.
  3. Edge cases: порожній вхід, помилка Neo4j, ChromaDB та Kafka, тайм-аут.
- **Дії.** Гілку «немає персонажів» спрямовано на перевірку `BEFORE`; умову змінено на `a < 3`; додано коди `GRAPH_UNAVAILABLE`, `TIMEOUT`, `EMBEDDING_FAILED`, `VECTOR_STORE_UNAVAILABLE`; для outbox введено ліміт спроб `M := 10` та метрику `outbox_dead_total`.
- **Не змінено.** Цикл по `BEFORE` без окремого тайм-ауту: кількість зв'язків обмежена 5 000 (SRS-NFR-PERF-03).

### Завдання 4. Інтеграційний аудит
- **Метод.** Скрипт зіставив ENUM у ERD, схеми OpenAPI та коди в алгоритмах; решту розбіжностей знайдено перегляду контейнерної діаграми.
- **Виявлено та виправлено** (докладно в розділі 2.7): розбіжність маршрутів на діаграмі та в OpenAPI; відсутній зв'язок Consistency Service → PostgreSQL; відсутнє обмеження `error_code` в API та БД.
- **Результат.** Блокерів немає; обмеження — контракт охоплює лише обрані сценарії.
