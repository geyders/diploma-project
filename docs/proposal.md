# Thesis Proposal

## Назва проєкту

**Назва продукту:** Novelize

**Українською:** Novelize — інформаційна система інтелектуальної підтримки процесу створення та редагування художніх творів

**English:** Novelize — an Intelligent Support System for Literary Text Creation and Editing

## Актуальність та проблематика

Процес створення художнього твору великого обсягу (роман, серія, сценарій) вимагає від автора одночасного контролю над двома різнорідними аспектами: структурною організацією матеріалу (розділи, сцени, персонажі, локації, хронологія подій) та якістю самого тексту (граматика, стиль, читабельність). Наявні на ринку рішення покривають ці задачі окремо: текстові редактори (Scrivener, yWriter) надають засоби структурування, але не мають інструментів автоматизованого аналізу тексту; граматичні перевірники (Grammarly, LanguageTool) аналізують текст, але не мають доступу до моделі сутностей твору (персонажів, локацій, таймлайну) і тому не здатні виявляти змістові суперечності — наприклад, невідповідність характеристик персонажа, порушення часової послідовності подій або суперечливе розташування дії.

Інженерна складність задачі полягає в необхідності поєднати в єдиній системі: (а) структуроване зберігання та версіювання ієрархічних сутностей твору; (б) асинхронну обробку природної мови значних обсягів тексту без блокування основного інтерфейсу; (в) моделювання сутностей твору та зв'язків між ними у формі, що дозволяє автоматизований пошук логічних суперечностей.

## Сформована ідея продукту

Розподілена веб-система на основі мікросервісної архітектури, що поєднує CRUD-функціональність для керування творами з окремими сервісами асинхронного NLP-аналізу тексту та графового аналізу узгодженості сюжету.

**Тип архітектури:** мікросервісна платформа з подієво-керованою (event-driven) взаємодією між сервісом контенту та сервісами аналізу.

## Детальний опис функціоналу (Core Features)

1. **Керування профілем автора та творами** — реєстрація/автентифікація, створення книг, ієрархічна структура розділів, сцен та текстових фрагментів з підтримкою версіювання правок.
2. **Реєстр сутностей твору** — створення та редагування карток персонажів (характеристики, взаємозв'язки), локацій, подій та хронології, збережених у графовій моделі даних.
3. **Асинхронний NLP-аналіз тексту** — перевірка орфографії, граматики, пунктуації; винесена в окремий сервіс, що обробляє задачі через черги повідомлень і не блокує редагування.
4. **Стилістичний аналіз та статистика** — виявлення повторів слів, надмірно довгих/складних речень, метрики читабельності, узагальнена статистика твору.
5. **Перевірка змістової узгодженості (Consistency Check)** — графові запити для виявлення суперечностей у характеристиках персонажів, часовій послідовності подій та локаціях; за потреби — генерація природномовного пояснення знайденої суперечності.
6. **Сповіщення про результати аналізу в реальному часі** — доставка статусу довготривалих задач аналізу через WebSocket/SSE, щоб автор не очікував синхронної відповіді.
7. **Спостережуваність та контроль якості** — метрики затримок обробки, моніторинг стабільності сервісів, автоматизована перевірка якості коду в CI/CD.

## Попередній інструментарій та технологічний стек

**Мови програмування:** Python (сервіси аналізу), TypeScript/Node.js (backend API, сервіс контенту)

**Архітектурні патерни:** Microservices, Event-Driven Architecture, CQRS (розділення операцій редагування та читання результатів аналізу), Outbox Pattern (гарантована доставка подій аналізу)

**Фреймворки:** NestJS або FastAPI (backend-сервіси), React (frontend)

**Бази даних:** PostgreSQL (профілі, твори, структура розділів), Neo4j або ArangoDB (граф сутностей твору — персонажі, локації, події, зв'язки), pgvector/ChromaDB (векторне сховище для семантичного пошуку повторів і протиріч)

**NLP/ML-інструменти:** spaCy / NLTK / LanguageTool (граматика, стиль, читабельність), sentence-embeddings моделі (семантична подібність фрагментів тексту)

**Брокер повідомлень:** Apache Kafka або RabbitMQ (асинхронні задачі аналізу)

**DevOps-інструменти:** Docker / Docker Compose, GitHub Actions (CI/CD), SonarQube (контроль технічного боргу), OpenTelemetry + Prometheus/Grafana (спостережуваність)
